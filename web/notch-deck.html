Creditcoin CC3 Testnet — cross-chain cashflow-backed lending

A cashflow can cross chains.
Its borrowing limit shouldn't.

Notch turns a proven Ethereum cashflow into a finite, shared financing capacity on Creditcoin — decoded from a real transaction, never typed, and never financeable past its own limit, no matter how many independent lenders draw against it.

02 / 07

The problem

The same future payment can look available more than once.

Lenders on different chains can't see each other's commitments. Each one, working alone, has no way to know whether a position has already been financed elsewhere — so the same verified cashflow can back more debt than it can ever repay.

A new chain doesn't create new collateral. It just makes an already-financed position look untouched to whoever looks next.

03 / 07

The wedge

A proven fact is not the same thing as a depletable claim.

This season's designs largely share one shape: prove an Ethereum fact, then let one or more systems read it and decide. That shape has a gap Notch is built to close.

Read-and-decide

The proven fact is reusable information — proved once, read independently by every lender's own decision.

  • Each lender keeps its own replay guard
  • Guards can't see each other
  • Nothing represents "how much is left" after someone else already spent against this exact position
  • Independent guards permit collective over-allocation

This season's shape: Attestcoin Tutorial 4, CrossCredit, CreditX, HashCredit — each proves a fact, then a decision system reads it.

Shared conserved capacity

The proven fact becomes one depletable resource, held once, on-chain, in a registry every lender consumes from.

  • One registry, one capacity per verified position
  • Every lender's draw reduces the same number
  • The next lender sees exactly what's left — including what strangers already took
  • Collective over-allocation is refused on-chain, atomically

Notch: 3,280 units of over-financing this exact gap prevented, measured against a per-lender-guard baseline on the same real positions. Full campaign in the appendix.

06 / 07

Where this goes — not what's demonstrated today

The same wedge applies to any depletable claim.

A locked cashflow stream is one instance of a broader shape: a real-world claim, proven once, whose remaining value needs to be shared and enforced across independent actors who can't otherwise see each other.

Invoices and receivables generalize the same registry: verify the receivable's existence and terms once, and let every factor or lender who advances against it draw from one conserved balance instead of trusting the borrower's word that it hasn't already been pledged elsewhere. Outbound repayment — completing the loop back to the source chain — is the natural v2 extension once Attestcoin's write path releases.

Not built. Not claimed of this demo. Named as direction, clearly separated from what's proven above.
